# Reading-state sync is hand-rolled, not a local-first sync library

Reading Progress, Bookmarks, Highlights and Read Status sync across devices through our own IndexedDB outbox and a `POST /api/sync` endpoint. Every record is merged with last write wins on hybrid logical clock (HLC) timestamps, and deletes are kept as tombstones. We considered local-first libraries, in particular Evolu, and rejected them. Evolu encrypts end to end under a per-owner secret, so the server cannot read the data, and that breaks Papyrus in three ways. The server has to cascade deletes and hide or restore state for Books, Files, Profiles and Shares. Library queries filter by Read Status. And with password-less Profiles, the server would have to hand every Profile's secret to whoever picks that Profile, so the encryption would protect nothing. A library would also cover only reading state, next to the server-owned Books and Shares in better-sqlite3 + Drizzle, which means two data layers and an extra relay process. The merge itself is per record over four small tables, which doesn't call for CRDT machinery. HLC timestamps, rather than raw device clocks, stop a device whose clock runs fast from winning every conflict.
